# Архитектура профилей Hermes (LOVA CERAMICS)

## Состав профилей

На сервере ONE DASH (89.125.17.86) работают 6 профилей плюс `default` (Гера).

**Точный состав, модели и зоны ответственности — в `meta/profile-delegate/ROUTING.md`.**
Тот файл генерируется из машинного реестра (`hermes profile describe` +
`hermes profile list`), поэтому не может разойтись с сервером. Таблица, которая
раньше стояла здесь, разошлась: `seo` значился на Gemini Flash, фактически работает
на DeepSeek; `dev` значился на Gemini Flash, фактически на Qwen 3.7 Max.

**Завести НОВЫЙ профиль — навык `meta/profile-forge`, там весь путь по шагам.**
Коротко: описать блок в реестре, `profile_forge.py render` + `install`, потом
обязательно `profile_acceptance.py <имя> --live`. Этот навык при этом править не надо.
`hermes profile create` не звать — он засевает 67 лишних навыков.

## Почему именно эти модели

Ниже — замысел выбора, а не текущее состояние. Что стоит на сервере сейчас — только в `ROUTING.md`.

Выбор модели под характер задач профиля:

- **Sonnet 5 для творческих задач** (content, writer) — даёт живой текст, справляется с фактчекингом. Gemini Flash на этом плывёт: шаблонные фразы, слабый фактчек.
- **DeepSeek V4 Pro для документов** (docs) — точно воспроизводит структуру шаблонов .docx. Gemini Flash ломает таблицы в счетах и КП.
- **Gemini 3.7 Flash для формульных задач** (seo, dev) — мета-теги, кластеризация, простые скрипты. Дёшево и быстро, глубина не нужна.
- **DeepSeek V4 Pro для стратегии** (default) — сложные решения, анализ, оркестрация.

### Антипаттерны (НЕ ДЕЛАТЬ)

- Gemini Flash на посты/литературу → шаблонный мёртвый текст
- Gemini Flash на .docx → сломанные таблицы, съехавшая вёрстка
- DeepSeek на всё → $51 за 3 дня вместо $50-80 в месяц

## Архитектура ботов

**Согласовано с клиентом 22.08.2026, вариант «C».** Telegram-бот один — Гера. Он
единственная точка входа и оркестратор. Профили — это профили hermes (изоляция по
`HERMES_HOME`), а не отдельные боты: у них нет своего токена и своего чата, и напрямую
с Микой они не переписываются.

Отдельный бот на каждый профиль (то, что планировалось раньше) отменено: Мике пришлось
бы помнить, кому из шести ботов писать, а вся ценность оркестратора в том, что помнить
не надо.

Полный gateway остаётся только у Геры. Профили поднимает диспетчер kanban, который
живёт внутри этого же gateway-процесса (`kanban.dispatch_in_gateway`, включён по
умолчанию) — отдельных процессов и юнитов на профиль не нужно.

### Как Гера отдаёт работу профилю

Через доску: `kanban_create(title=…, assignee=<профиль>, body=…, max_runtime_seconds=…)`.
Подробности, формат тела задачи и что отвечать Мике — навык `meta/profile-delegate`.

Вызывать профиль из терминала **нельзя**:

```bash
hermes --profile docs chat -q 'задача'   # ← так не работает
```

Замерено 27.08.2026: реальная документная задача в профиле идёт 12–16 минут, а таймаут
терминала у Геры — 180 секунд. Синхронный вызов убивается таймаутом всегда, работа
теряется. Диспетчер запускает профиль сам, тем же способом, но фоном и со своим
бюджетом времени.

## Связь с model-router

Этот навык — архитектурный. `model-router` — операционный (какую модель дёргать через API для конкретной задачи). Они дополняют друг друга: architecture говорит «какой профиль на какой модели сидит», router говорит «какую модель вызвать для генерации».

## Профили на диске

```
/root/.hermes/profiles/<имя>/
├── SOUL.md      → кто это и как работает
├── config.yaml  → модель, max_turns, память
├── .env         → ключи
└── skills/      → навыки профиля (симлинки в /root/.hermes/skills/)
```

Зоны ответственности здесь не дублируются — они в `ROUTING.md`.
