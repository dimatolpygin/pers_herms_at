# Как завести нового агента-профиля

Читай это, когда Мика просит **нового специалиста**: «сделай мне агента по здоровью»,
«нужен отдельный агент по финансам», «заведи бота, который следит за анализами».

Ты можешь сделать это сам, целиком, из терминала. Пять команд.

## Чего делать НЕЛЬЗЯ

**Не зови `hermes profile create`.** Он засевает в профиль полный поставочный комплект
из 67 навыков: промпт раздувается вчетверо, профиль начинает «забывать» собственные
правила, и потом это вычищают руками. Так были заведены прежние шесть профилей, и пять
из них оказались нерабочими.

**Не пиши профилю `SOUL.md` и `config.yaml` руками.** Они генерируются. Ручная правка
проживёт до первой пересборки и потеряется молча.

**Не правь `profiles/registry.yaml` внутри `/opt/pers_herms_at`.** Этот каталог —
клон репозитория, деплой обновляет его через `git reset --hard`, и твоя правка исчезнет
вместе с профилем. Для профилей, заводимых здесь, есть отдельное место — см. шаг 1.

## Шаг 1. Описать профиль

Один файл на профиль в `/root/.hermes/registry.d/`. Деплой этот каталог не трогает.

```bash
mkdir -p /root/.hermes/registry.d
```

Записать `/root/.hermes/registry.d/health.yaml` (пример — под задачу меняй):

```yaml
profiles:
  health:
    title: "Здоровье"
    model: deepseek/deepseek-v4-pro
    critic: qwen/qwen3.7-max
    critic_why: >-
      Cross-check DeepSeek -> Qwen. Где дозировки и показатели, критик обязан быть
      из другой семьи моделей: своя повторит собственную ошибку.
    describe: >-
      Здоровье Мики: расшифровка анализов, дневник показателей и динамика,
      подготовка вопросов к приёму, отслеживание приёма препаратов.
      Не сюда: счета из клиники и налоговые вычеты — это docs.
    duties:
      - "Расшифровка результатов анализов"
      - "Дневник показателей и динамика по времени"
      - "Подготовка вопросов к приёму врача"
    artifacts: /root/.hermes/artifacts/health
    env_passthrough:
      - OPENROUTER_API_KEY
    skills:
      ocr-and-documents: productivity/ocr-and-documents
    guard:
      enabled: false
      what: "здоровье: анализы, показатели, назначения"
      markers: []
```

Четыре поля, в которых легко ошибиться:

- **`describe`** — по нему выбирается исполнитель задачи. Фраза «**Не сюда:** …»
  обязательна, проверка её требует: с восемью профилями зоны пересекаются, и это
  единственное, что удерживает задачу от ухода не туда.
- **`critic`** — обязательно другая семья моделей, иначе это не проверка.
- **`artifacts`** — абсолютный путь. Рабочий каталог задачи удаляется после
  завершения; файл, записанный внутрь него, пропадёт, и задача будет выглядеть
  сделанной при отсутствующем результате.
- **`skills`** — только нужное. Слева имя, справа путь в `/root/.hermes/skills/`.
  Проверь, что путь существует: `ls /root/.hermes/skills/<путь>`.

Проверить описание, ничего не устанавливая:

```bash
python3 /opt/pers_herms_at/scripts/profile_forge.py --check
```

## Шаг 2. Собрать и поставить

```bash
python3 /opt/pers_herms_at/scripts/profile_forge.py render health
python3 /opt/pers_herms_at/scripts/profile_forge.py install health
```

Занимает секунды. Профиль встаёт пустым (без лишних навыков), получает доступ к
ключам, свои навыки ссылками, каталог артефактов, описание для распределения задач.
Твой справочник «кому какая задача» обновляется сам.

Посмотреть, что будет сделано, ничего не меняя: добавь `--dry-run`.

## Шаг 3. Приёмка — без неё профиль не выпускается

```bash
python3 /opt/pers_herms_at/scripts/profile_forge.py --check    # если правил реестр
python3 /opt/pers_herms_at/scripts/profile_acceptance.py health --live
```

Без `--live` — пятнадцать быстрых проверок. С `--live` профилю ставится настоящая
задача и проверяется, что файл действительно появился. Это единственная проверка,
доказывающая, что профиль работает, а не просто установлен.

Чтобы живая проверка была осмысленной, допиши в реестр:

```yaml
    acceptance_probe:
      title: "Приёмка health: разбор анализа"
      body: >-
        Приёмочная проверка, не боевая задача. ...чёткое маленькое задание...
        Готовый файл положи в /root/.hermes/artifacts/health и верни путь.
      max_runtime: 20m
```

**В приёмочных задачах не выдумывай реквизиты организаций** — ты сам проверяешь
ИНН и ОГРН по контрольной сумме и отказываешься работать с несуществующими.
Пиши либо настоящие данные, либо задание, где реквизиты не нужны.

Результат `ПРОШЁЛ` — можно пользоваться. `НЕ ПРОШЁЛ` — в выводе написано, что именно.

## Шаг 4. Сказать Мике

Коротко: профиль такой-то поднят, вот что он умеет, приёмку прошёл, задачи ему
уходят через доску. Дальше просто ставь ему задачи через `kanban_create(assignee="health", …)`.

## Когда что-то мешает

**«На доске есть работающие задачи»** — установка отказалась работать. Это защита:
перезапуск шлюза убивает работающего исполнителя, его задача считается упавшей и после
двух попыток бросается. Дождись `hermes kanban list --status running` пустым.

**Профиль не берёт задачи** — проверь, что имя в `assignee` написано ровно как в реестре.
Карточка с неизвестным именем молча висит в очереди вечно.

**Задача упала с «Iteration budget exhausted»** — не увеличивай число ходов вслепую,
ограничивай время: `--max-runtime 30m` у задачи. По умолчанию в реестре стоит 80 ходов,
этого хватает; при 30 профиль однажды сделал документ и не успел закрыть карточку.

## Перенести профиль в репозиторий

Профиль из `/root/.hermes/registry.d/` живёт на сервере и переживает деплой, но не
переживёт потери сервера. Когда профиль устоялся, скажи Мике, что блок стоит перенести
в `profiles/registry.yaml` репозитория — это делается через того, кто может пушить в git.
Сам не пытайся: у клона на сервере нет учётных данных на запись.

## Что этот конвейер не решает

Скажи прямо, если спросят:

- Профили пока смотрят в один общий файл ключей. Для здоровья и финансов это
  стоит развести — отдельная работа, не входит в сделанное.
- Общая память не разделена на «общее о Мике» и «личное профиля».
- Критик вызывается самим профилем по инструкции, а не штатным механизмом проверки.
