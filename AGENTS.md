## 1. Что за проект

Делаем **персонального ИИ-агента «под ключ»** для клиента (Mironov / Mika). Это не просто бот —
это агентная оболочка **Hermes Agent** (NousResearch, `github.com/NousResearch/hermes-agent`),
настроенная под клиента и расширенная навыками.

**Что агент должен уметь (итоговая цель проекта):**
- Telegram-бот: ввод **текст + голос**, ответы по смыслу.
- **Долгосрочная выборочная память** о пользователе (факты, привычки, договорённости).
- Свой **стиль общения** («кореш/друг» на «ты», тёплый, но дельный).
- Решение задач по **коду и текстам**: мелкий код → блоком в чат, крупный → файлом; генерация
  **КП (.docx)** и **отчётов (.csv)**.
- **Автопостинг в соцсети** (гибкий сценарий, «Вариант 3»): по свободной команде/описанию/ссылке
  (в т.ч. Tilda) агент готовит **3 версии текста** + **картинку** (генерация/обработка фона), сам
  уточняет *куда* и *когда*, и публикует через **PostMyPost**; отложенный постинг — по cron.

**Заказ и объём** — см. переписку с клиентом: `C:\Users\GigaChat\Downloads\ЗАКАЗЫ\ии_агент_перс\переписка.txt`
(не в git). Бюджет ~20-25к, внедряем поэтапно. Выбран «Вариант 3» (с генерацией фото).

## 4. Методология ведения (okplan) — соблюдать строго

Прогресс держится на **трёх слоях правды** с приоритетом. Если противоречат — верь нижнему:

1. **`docs/STATUS.md`** — компактный снимок (легче всего устаревает).
2. **Чекбоксы в `docs/07_ROADMAP.md`** — `[ ]`/`[x]` по каждому критерию приёмки.
3. **Git-теги `stage-N-done`** — машинная правда о закрытии этапа.

**Приоритет: тег > чекбоксы > проза STATUS.** Нет тега `stage-N-done` → этап N НЕ закрыт.

### Ритуал старта сессии (обязательно)
1. Прочитать `docs/STATUS.md`.
2. `git tag -l "stage-*"` — сверить с таблицей в STATUS.
3. `git log --oneline -10` — что менялось последним.
4. Открыть `docs/07_ROADMAP.md` на текущем этапе.

### Взятие этапа в работу
1. В STATUS: обновить «Текущий этап» + «Активная работа», статус 🚧 в таблице.
2. Отдельный коммит: `chore(status): start stage N`.

### Закрытие этапа (порядок важен — тег ПОСЛЕДНИМ)
1. Все чекбоксы критериев в ROADMAP отмечены `[x]` и **реально проверены человеком** (живой тест).
2. Зафиксировать конкретику верификации (что проверили, что в логах/файлах).
3. Коммит `chore(status): close stage N`, затем `git tag stage-N-done -m "..."`.
4. В STATUS: ✅ в таблице, заполнить «Закрывающий тег», «Последний коммит», «Дата»; добавить
   запись в «Историю закрытий»; указать новый текущий этап.

> **Самопроверочный хэш в таблице**: после `git commit` хэш фиксируется; если используешь
> `--amend`, хэш меняется — впиши финальный хэш отдельным маленьким коммитом, чтобы поле
> «Последний коммит» совпадало с тегированным коммитом (см. как это сделано в истории git).

### Антипаттерны (методология не прощает)
- Тег/галочка **наперёд** (до живой проверки).
- STATUS как свалка (он — снимок на экран; детали → ROADMAP, git log).
- Закрывать этап без человеческой верификации.

### Принцип работы с человеком
**После каждого этапа — мини-отчёт человеку и человеческая проверка функционала** (где возможно —
прямо в Telegram). Claude/агент НЕ закрывает этап сам. Человек = Анастасия (разработчик).

## 6. Как запускать и чинить hermes

Путь к бинарю (PATH может быть не подхвачен в свежей сессии):
`%LOCALAPPDATA%\hermes\hermes-agent\venv\Scripts\hermes.exe`

- **Запустить бота**: `hermes gateway --accept-hooks` (long-running, polling). Лог — `logs/gateway.log`,
  ждать строку `Press Ctrl+C to stop`.
- **Веб-панель**: `hermes dashboard --no-open` → http://127.0.0.1:9119 (сессии, логи, чат, правка
  `.env`/конфига). На localhost без авторизации.
- **Разовый запрос (CLI-тест без Telegram)**: `hermes chat -q "вопрос" -Q --max-turns N`.
  Использует тот же конфиг/SOUL/память — удобно для проверки механизмов.
- **Рестарт gateway после правки `.env`/`config.yaml`** (обязателен — читаются при старте). Чисто
  гасить только gateway, не задев дашборд:
  ```powershell
  Get-CimInstance Win32_Process -Filter "Name='hermes.exe' OR Name='python.exe'" |
    Where-Object { $_.CommandLine -match 'gateway' -and $_.CommandLine -notmatch 'dashboard' } |
    ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
  ```
  затем снова `hermes gateway --accept-hooks`.
- **Правка `SOUL.md`** — рестарт НЕ нужен, достаточно `/new` в чате.
- Telegram игнорирует `/start` (служебный пинг) — это by design, не баг. Для теста писать обычный текст.

## 7. Важные решения и подводные камни (не наступи повторно)

- **OpenRouter-ключи бывают двух типов.** Ключ клиента из `доступы.txt` (`cedd…`) —
  **provisioning/management** (`is_management_key: true`): им НЕЛЬЗЯ делать инференс (даёт
  `401 "User not found"`), только управлять ключами. Для инференса нужен обычный ключ
  (можно сгенерить из provisioning через `POST https://openrouter.ai/api/v1/keys`). Сейчас в
  `.env` стоит dev-ключ Анастасии (`0870…`, рабочий). **На прод нужен инференс-ключ аккаунта клиента.**
- **Боты: dev vs prod.** Локально — `@NEIRO_BRAIN01_BOT` + id Анастасии `2042819654`. Прод —
  `@Mironov_AgentBot` + Mika `5183294551`. Переключение на этапе 7 (деплой). Прод-значения — в
  комментариях `.env` и в `доступы.txt`.
- **DeepSeek подмешивает китайские иероглифы** в память/текст. В `SOUL.md` есть правило «память
  только по-русски». Если всплывёт в других местах — добавляй аналогичные инструкции.
- **Память**: явные «запомни» нужно сохранять немедленно (правило в SOUL.md), иначе при коротком
  диалоге + `/reset` факт теряется до флаша.
- **Playwright Chromium не установлен** (ECONNRESET при инсталле) — браузерные инструменты не
  работают. Доустановить при необходимости: `cd %LOCALAPPDATA%\hermes\hermes-agent && npx playwright install chromium`.

## 8. Безопасность и git-конвенции

- **Секреты НЕ коммитить.** `.gitignore` исключает `доступы.txt`, `env_пример.txt`, `переписка.txt`,

- **Коммиты статуса — отдельно от кода**: `chore(status): start/close stage N`. Чекбоксы можно
  отмечать вместе с реализующим кодом.
- Перед закрытием/деплоем — никаких тегов и галочек «на словах».
