занятой доске. Повторный живой прогон `docs` после этого прошёл чисто (`t_264faa91`,

**Опорная находка этапа (машинно, 28.08.2026)**: конвейер писать с нуля не надо — в hermes есть
**дистрибутивы профилей**. `hermes profile install <git-URL | каталог>` ставит профиль по манифесту
`distribution.yaml`, `hermes profile update <имя>` перекатывает его из источника, **не трогая**
память, сессии, `auth.json` и `.env`. Это ровно инвариант 4 («профиль живёт в git»), закрытый
штатно. Два свойства, важные для нас: (1) установка из дистрибутива **не засевает** поставочные
навыки — профиль встаёт пустым, отдельная диета не нужна; (2) символические ссылки внутри
дистрибутива **запрещены** (`_reject_distribution_symlinks`), поэтому `skills/` в манифест не
кладём — навыки профиля остаются симлинками в `/root/.hermes/skills/` и раздаются форджем.
Седьмой случай подряд, когда движок уже в поставке.

## Протокол обновления

**При старте сессии**:
1. Прочитать этот файл.
2. `git tag -l "stage-*"` и сверить с колонкой «Закрывающий тег». Тег без записи в таблице = таблица устарела, обновить.
3. `git log --oneline -10` — что менялось последним.
4. Только после этого приступать к работе.

**При взятии этапа в работу**:
1. Обновить «Текущий этап» и «Активная работа».
2. Статус 🚧 в таблице.
3. Закоммитить отдельно: `chore(status): start stage N`.

**При закрытии этапа**:
1. Убедиться, что все чекбоксы в `07_ROADMAP.md` отмечены `[x]` и реально проверены человеком.
2. Создать тег: `git tag stage-N-done -m "<описание>"`.
3. В таблице: ✅, «Закрывающий тег», «Последний коммит» (`git rev-parse --short HEAD`), «Дата закрытия».
4. Добавить запись в «Историю закрытий».
5. Указать новый «Текущий этап» и «Следующий шаг».
6. Закоммитить: `chore(status): close stage N`.

**Если этап заблокирован**:
1. Статус ⏸ в таблице.
2. В «Известные блокеры»: что блокирует, кого ждём, что нужно для разблокировки.
