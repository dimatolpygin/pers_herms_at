# Память агента: оглавление + внешние заметки (этап 14)

Как устроена долгосрочная память Геры после переделки 2026-07-16.
Здесь только архитектура — сами заметки лежат вне git (в них личные данные).

## Проблема

Агент сообщил: «память заполнена на 68%, темп ~15–20% в неделю, ещё 1–2 недели —
и начну терять важное». На момент разбора было хуже: **9 765 / 10 000 = 97,7%**.

Разбор по исходникам hermes показал, что переполнение — **не баг, а следствие
конструкции**:

- `MEMORY.md` и `USER.md` целиком вшиваются в системный промпт **замороженным
  снимком** на старте сессии (это защищает prefix-кэш).
- Лимит задан в символах (`memory.memory_char_limit`, на проде 10 000).
- **Авто-сжатия нет by design**: при переполнении tool `memory` возвращает
  ошибку, и агент обязан освободить место сам.

То есть в бюджет промпта клали **тела** фактов. Плюс два усилителя:
`background_review` (форк агента после хода сам решает, что записать — сработал
21 раз за 2000 строк лога) и нудж каждые 10 ходов. Память писала машинерия,
а чистить её было некому.

**Что реально забивало память** — не факты, а мусор: сервер записан трижды
почти дословно, про основную модель лежали ЧЕТЫРЕ взаимоисключающие записи,
дубли про проактивность/FAL/оформление.

## Решение

В промпте — **только оглавление**. Тела — файлами снаружи.

```
MEMORY.md (в промпте, ~12%)          notes/ (на диске, вне промпта)
┌──────────────────────────────┐     ┌────────────────────────────┐
│ 📇 ОГЛАВЛЕНИЕ                │     │ posts-design.md            │
│ Оформление постов … →────────┼────►│ posting-tech.md            │
│ Деньги и сервисы … →─────────┼────►│ services-budget.md         │
│ Сервер … →───────────────────┼────►│ server.md                  │
│ (одна строка на тему)        │     │ … тела, таблицы, цифры     │
└──────────────────────────────┘     └────────────────────────────┘
```

- **Чтение**: тема всплыла → агент находит строку и открывает файл `read_file`.
- **Запись**: тема есть → тело дописывается в её файл, оглавление не растёт.
  Темы нет → новый файл + одна строка-указатель.
- **Переполнение**: лимит стал не проблемой, а **принуждением** — при ошибке
  лимита агент выносит тела в заметки, а не удаляет факты.

Движок не писали: `read_file` / `write_file` / `search_files` уже в ядре
тулсета, а оглавление живёт в штатном `MEMORY.md` — его hermes и так грузит.

## Где что лежит

| Что | Где | В промпте? |
|---|---|---|
| Оглавление | `~/.hermes/memories/MEMORY.md` | да, целиком |
| Профиль Мики | `~/.hermes/memories/USER.md` | да, целиком |
| Тела фактов | `~/.hermes/notes/*.md` | нет, по требованию |
| Архив заметок | `~/.hermes/notes/.archive/` | нет |
| Правила и характер | `~/.hermes/SOUL.md` | да |
| Правила «как делать» | навыки (`skill_manage`) | по требованию |
| Хронология сессий | `~/.hermes/session_memory.md` | нет |

Протокол записан в SOUL.md (раздел «Память: оглавление и заметки») — он
всегда в промпте, поэтому действует и на `background_review`.

## Уборка

Ежедневная задача (нативный `cronjob`, 05:00 МСК, `--deliver local` — молча):
склеить дубли, убрать протухшее, починить висячие ссылки, вынести уехавшие в
оглавление тела.

**Железное правило: уборка ничего не удаляет.** Максимум — `mv` в
`notes/.archive/`. Это повторяет принцип родного куратора hermes («never
auto-deletes — the worst outcome is archival, which is recoverable»).

Правило появилось не от хорошей жизни: первая версия промпта разрешала `rm`, и
уборка **снесла заметку о предстоящей поездке** (18–25.07) за три дня до неё,
приняв пометку «временная» за разрешение. Отсюда же второе правило: устаревшим
считать только то, у чего **дата окончания уже прошла** — сверяясь с реальным
`date`, а не с пометкой в заголовке.

## Результат

| | Было | Стало |
|---|---|---|
| `MEMORY.md` | 9 765 / 10 000 (**97,7%**) | ~1 240 (**~12%**) |
| `USER.md` | 4 443 / 6 000 (**74%**) | ~1 270 (**~21%**) |
| Тела фактов | в промпте | ~9,5 КБ в заметках |

Главное — не разовая цифра, а то, что **новые факты больше не растят память**:
проверено живым прогоном (агент записал объёмный факт → тело ушло в заметку,
оглавление не изменилось ни на байт).

## Чего не делали

Сторонний бэкенд памяти (mem0 / honcho / OpenViking — hermes умеет 8 штук) не
подключали: решение клиента, задача решается штатными средствами.
